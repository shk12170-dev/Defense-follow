# 내부자 정보유출 대응 플레이북 (1쪽)

대상: 대시보드/경보로 R1(대량 조회)·R3(비활성 계정)·R4(조회 후 반출)가 발생했을 때. 담당: 보안 담당자 + 관리자.
*법령·기관 신고 기준은 시행 시점에 확인한다. 아래 시한은 일반적인 기준이다.*

## 0. 평시 준비
- 해제 전용 관리자 계정(`admin02`)을 분리해 둔다 (잠긴 관리자 복구용).
- 규칙 임계값(`rules/rules.yaml`)을 실로그로 주기적으로 점검한다.
- 감사 로그 무결성을 정기 점검한다: `python scripts/verify_audit.py`

## 1. 탐지·분류 (목표 5분 이내)
| 경보 | 의미 | 우선 확인 |
|---|---|---|
| R4 critical | 대량 조회 후 반출 | 반출 건수·사유, 내보내기 로그 |
| R1 high | 짧은 시간 대량 조회 | 조회 건수, 업무 사유(바쁜 시간 오탐 여부) |
| R3 high | 비활성·잠금 계정 접근 | 계정 도용·퇴사자 접근 여부, 접속 IP |
| R7 critical | 대량 조회 직후 내보내기를 서버가 **사전 차단**(반출 없음, 계정 잠금 없음) | 직전 조회 내역과 사유, 계정 도용 여부 |
| R8 medium | 본인 평소 대비 조회량 급증 (경고만, 잠금 없음) | 오늘 조회 건수와 평소 평균, 업무 변화 여부 |
| R6 high | 하루 누적 조회량 위험 (계정 자동 잠금) | 하루 조회 합계, 업무 사유 (저속 반출 의심) |
| R5 medium | 하루 누적 조회량 경고 (계정 유지) | 오늘 조회 추이, 다음 단계(R6) 도달 여부 |
| R2 medium | 새벽 접근 | 야근·장애 대응 등 정당한 사유 |

대시보드에서 계정·시각·근거(`rows_in_window` 등)를 확인하고 정탐/오탐을 1차 판단한다.

## 2. 격리
- high 이상은 **계정이 이미 자동 잠금**된다 (`response.lock` 이벤트 확인).
- 같은 계정의 기존 토큰은 즉시 무효다. 추가로 의심 IP·동일 부서 계정의 최근 활동을 점검한다.
- **오탐으로 확인되면** 대시보드의 "잠금 해제"(또는 `POST /admin/users/{username}/unlock`)로 복구한다. 해제 시 감시 이력이 초기화된다.
- 휴면·퇴사 계정은 해제 대상이 아니다. 계정 정책에 따라 처리한다.

## 3. 원인 분석·범위 산정
1. `GET /audit?username=<계정>` 으로 해당 계정의 조회·내보내기 이력을 시간순으로 확인한다.
2. 이벤트별 `rows`를 합산해 **유출 가능 건수**를 산정한다 (`customer.list/search/view/unmask/export`).
3. `customer.unmask`(마스킹 해제)와 사유(`reason`)를 확인한다. 내보내기는 마스킹 상태이므로, 해제 이력과 대조한다.
4. 로그 변조 여부를 검증한다: `python scripts/verify_audit.py` (실패 시 변조 의심 줄 번호 출력).

## 4. 통지·보고
- 개인정보 유출이 확인되면 법령상 시한 내에 정보주체 통지와 관계 기관 신고가 필요하다 (일반적으로 **인지 후 72시간 이내**, 규모·민감정보 여부에 따라 대상 상이 — 최신 기준 확인).
- 사내 보고: 발생 시각, 영향 계정·건수, 조치 내역, 추가 조치 계획.

## 5. 복구·재발방지
- 필요 시 비밀번호 재설정과 권한 재검토(최소 권한 원칙) 후 계정을 복구한다.
- 규칙 튜닝: 정탐은 해당 우회 패턴을 규칙에 반영하고, 오탐은 임계값·예외 조건을 조정한다 (오탐과 유출 규모의 균형, `/report` 참고).
- 사후 점검: 이번 사건을 보고서로 남기고 훈련 시나리오(`scripts/attack_sim.py`)에 반영한다.

## 6. 알려진 한계 (대응 시 유의)
- 하루 1,200건 미만(분당 약 2.5건 이하)의 아주 느린 조회는 탐지하지 못한다 → 주간 누적 조회량을 수동 점검한다.
- 조회 경보는 요청 처리 시점에 발생하고 잠금은 다음 요청부터 적용되므로, 잠금 이전의 **조회 유출분**(R1 기준 최대 약 300건)을 범위에 포함한다. 내보내기는 사전 차단되지만, 조회를 200건 미만으로 나눠 읽은 뒤 내보낸 경우는 막지 못한다.
- R7은 반출만 막고 계정을 잠그지 않는다. 보안 담당자가 직접 확인해 계정 조치를 결정한다.
